# 五、项目经验

## 5.1 海外聚合 SDK 统一接入体系（账号登录 / 支付 / 广告，0-1 架构设计）

**背景** HAGO 面向东南亚、中东、南美等海外市场，需接入 Google/Facebook/TikTok 账号登录、Google Play 内购以及 Pangle/AdMob/Meta 等多平台第三方 SDK。各家 API 形态各异、版本迭代频繁，业务代码直接依赖 SDK 导致耦合度高、接入成本高，升级与隐私合规整改成本大。

**方案** 从 0 到 1 主导聚合 SDK 架构设计：统一抽象层屏蔽各家 SDK 差异，业务侧通过统一接口接入、不感知底层 SDK 变化；沉淀统一接入规范与开发文档，业务方按文档即可完成接入与集成。

- **账号登录：** Google / Facebook / TikTok 多渠道登录归一为统一登录态，回调归一，渠道切换与扩展对业务透明。
- **支付：** Google Play 内购 (IAP) 接入，统一订单与发货校验流程，保证支付链路一致性。
- **广告：** Pangle / AdMob / Meta 多平台广告统一抽象，激励视频、插屏、Banner 回调归一，支持广告源兜底与降级策略。

**成果** 业务方接入成本显著降低，登录与广告渠道可替换、可并行；第三方模块编译期按需引入、运行期按线上配置启停，按地区市场灵活适配，支撑多机型、多系统版本下的高稳定性与低接入成本。

## 5.2 Android & iOS 双端一致性网络层（2023-2024）

以 Protobuf 协议为唯一真相源，编写代码生成工具自动产出 Android / iOS 两端网络代码，统一状态码与错误处理规范，双端在重试、降级等场景行为一致。覆盖全部核心业务模块，协议变更只需更新 proto 重新生成，联调效率提升 70% 以上，消除两端接口不一致导致的生产事故。

## 5.3 直播间容器化 / 插件化架构（2020-2022）

直播间承载语聊房、直播、小游戏等多种业务形态，设计容器化/插件化架构：每种形态作为独立插件模块，编译期按需组合、未使用插件零体积引入，宿主-插件通信协议统一，插件注册与发现基于 5.4 的 Service Manager 自动完成。20+ 房间模块独立开发测试互不干扰，支持不退出直播间秒级热切换业务形态，新增形态无需修改宿主代码，迭代周期从周级缩短到天级。

## 5.4 跨模块通信与 MVVM 架构框架（2018-2022，贯穿至今）

HAGO 架构基座，后续所有项目均构建于此框架之上：模块间基于 KSP 编译期生成服务注册与发现的 Service Manager，避免运行时反射开销；模块内统一 MVVM 架构，ViewModel 绑定业务 Context 而非页面生命周期。团队 20+ 开发者日常使用，承载 HAGO 全部 100+ 业务模块的通信与架构规范。

## 5.5 单向数据流状态管理框架（2025）

设计细粒度状态订阅机制，状态按属性分发而非整对象通知，消除 UI 冗余刷新；Compose 与传统 View 统一状态消费 API，一套 ViewModel 在两种 UI 范式下行为一致。已接入直播间、主页、导航等核心模块。

## 5.6 稳定性与性能治理（2023-2024）

内存泄漏治理（协程生命周期自动绑定，内存泄漏相关崩溃率显著下降）、UI 刷新性能优化（刷新频率降低约 40%）、iOS 包体积治理（脚本压缩大尺寸图片、非首屏图片改为网络按需加载，安装包减小约 10MB），多维度提升 App 稳定性与健壮性。
