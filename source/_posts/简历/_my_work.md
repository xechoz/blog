# 五、项目经验

## 5.1 跨模块通信与 MVVM 架构框架（2019-2023，持续演进）

**业务背景** 业务从单体快速扩张至 100+ 模块（语聊、直播、小游戏、社交、商业化），各业务线并行迭代、能力互用需求激增；模块间通信靠人肉约定，接口与实现无编译期保障，跨模块联调频繁出错；模块内结构随开发者习惯各异，同一逻辑在不同页面各写一套，新人接手与跨团队协作成本高，严重拖慢业务迭代节奏。

**方案** 主导模块化架构设计，负责整体拆分方案与通信规范制定。模块间——服务发现与管理：基于 KSP 编译期生成服务注册与发现代码，避免运行时反射开销，接口与实现编译期即可校验；模块内——MVVM 统一架构：ViewModel 绑定业务上下文 Context 而非页面生命周期，为各模块提供一致的子功能组织与数据共享范式。

**成果** 团队 20+ 开发者日常使用，新增模块只需定义接口与实现，框架自动完成注册分发；模块间由人肉约定转为编译期保障，跨模块联调事故显著减少，语聊、直播、商业化等业务线可并行独立迭代、能力互用；模块内结构统一后，新人接手周期大幅缩短，交接成本显著降低；框架持续演进至 2025 年，承载 HAGO 全部 100+ 业务模块的通信与架构规范，成为支撑业务团队高效迭代的基础设施。

## 5.2 业务状态管理架构（单向数据流，2025）

**业务背景** 直播间、主播主页、多级导航等核心高频刷新场景，状态流复杂、刷新粒度粗、生命周期依赖手动管理，导致线上问题反复出现、排查成本高；各模块状态管理各写各的，缺乏全局一致解法，直接影响核心业务的稳定运行与迭代效率。

**方案** 设计细粒度状态订阅机制，状态按属性分发而非整对象通知，从机制上减少冗余刷新；协程生命周期与状态管理器自动绑定，开发者无需手动管理，从源头降低内存泄漏风险；与既有 MVVM、Service 体系原生集成，跨页面/跨模块共享同一套 setState 更新规范，无额外学习成本。

**成果** Compose 与传统 View 统一状态消费 API，一套 ViewModel 在两种 UI 范式下行为完全一致，迁移零摩擦；已覆盖直播间、主页、导航等核心业务模块，从机制上消除此类线上问题根因，核心高频场景的稳定性与可维护性显著提升，为后续业务迭代提供统一的状态管理基线。

## 5.3 Android & iOS 双端网络层（跨端方案拉通，2023-2024）

**业务背景** HAGO 面向东南亚、中东、南美等多市场，Android 与 iOS 各自维护独立网络层，接口定义靠文档传递，一次协议变更两端对齐联调耗时数天；弱网、多市场环境下异常处理不一致，容易引发线上问题，成为业务迭代与跨端协作的最大瓶颈。

**方案** 以 Protobuf 协议文件作为唯一真相源，编写代码生成工具自动产出 Android 与 iOS 两端网络调用代码，统一跨端方案。统一状态码体系、错误分层、鉴权失效处理、超时重试、降级兜底等网络行为，保证双端异常处理一致，业务方无需感知平台差异。

**成果** 覆盖 Android 与 iOS 全部核心业务模块。协议变更只需更新 proto 文件并重新生成，双端联调从数天缩短至小时级；消除两端接口不一致导致的生产事故，保障出海多市场环境下核心业务接口的稳定运行与交付效率，业务迭代不再受跨端联调阻塞。

## 5.4 海外第三方 SDK 统一接入体系

**业务背景** HAGO 面向东南亚、中东、南美等海外市场，需接入 Google/Facebook/TikTok 登录、Google Play 内购以及 Pangle/AdMob/Meta 等多平台广告 SDK，直接支撑账号体系与商业化收入。各家 API 形态各异、版本迭代频繁，业务代码直接依赖 SDK 导致耦合度高，升级与隐私合规整改成本大，影响商业化策略的快速调整。

**方案** 设计统一 SDK 接入层屏蔽各家差异，业务侧通过统一接口接入、不感知底层 SDK 变化。

- **登录：** Google / Facebook / TikTok 多渠道登录归一为统一登录态，渠道切换与扩展对业务透明，保障账号体系与获客链路稳定。
- **支付：** Google Play 内购 (IAP) 接入，统一订单与发货校验流程，保证支付链路一致性，支撑商业化收入稳定。
- **广告：** Pangle / AdMob / Meta 多平台广告统一抽象，激励视频、插屏、Banner 回调归一，支持广告源兜底与降级策略，保障广告收入稳定性。

**成果** 业务方接入成本显著降低，登录与广告渠道可替换、可并行，商业化策略可快速调整；第三方模块编译期按需引入、运行期按线上配置启停，灵活适配不同地区市场的合规与业务需求。
